## Purpose

This document defines what complete ViewTube means. It does not maintain detailed tasks, PR logs, agent handoffs, or domain implementation internals.

## Completion north star

ViewTube behaves as one continuous creator system:

YouTube/account/data
→ VT-SYNC
→ analytics-canon
→ evidence and intelligence
→ BrainRuntime
→ Project + ContentBuild
→ generation and durable assets
→ package
→ Editor/Remotion
→ approved publish
→ YouTube
→ post-publish analytics
→ outcomes/evaluation
→ governed learning
→ improved future decisions.

Completion means that loop is production-reachable, attributable, recoverable, measurable, understandable to the creator, and governed.

## Non-negotiable product invariants

1. One canonical owner per fact/state class; adapters and projections do not create competing truth.
2. Missing is not zero. Synthetic/demo data is never presented as live creator data.
3. Identity survives handoffs: channel, project, ContentBuild, asset/version, operation, approved package, publish binding, outcome and evaluation remain traceable.
4. Recommendation, creator approval, execution, receipt, outcome and learning are separate stages.
5. External side effects retain approval, idempotency, retry, recovery and reconciliation boundaries.
6. BrainRuntime orchestrates creator reasoning; specialist intelligence remains specialized; analytics truth remains analytics-canon.
7. Durable learning is governed promotion, never silent memory mutation from one observation.
8. Product surfaces share capabilities rather than recreating independent backends/state owners.
9. A simpler correct canonical system is preferable to a sophisticated duplicated one.
10. Current implementation claims require evidence. Implemented is not Verified; Verified is not automatically Released.
11. Visible work is complete only after appropriate runtime interaction and visual/responsive inspection.
12. Accessibility, mobile usability, recoverability, truthful states and natural creator comprehension are product completion requirements, not polish.
13. Dead paths and duplicate authorities are part of completion work once parity and rollback safety are proven.
14. Every meaningful capability can be traced to an owner, authority, current work state, evidence and next gate.

## Creator lifecycle

Discover → Validate → Design → Produce → Assemble → Package → Publish → Engage → Learn → Operate.

The product may expose many surfaces, but it is one lifecycle.

## Global health dimensions

Executive health is derived from governed records, not manually asserted percentages:
- architecture coherence;
- backend implementation;
- frontend implementation;
- cross-system integration;
- automated tests;
- runtime proof;
- responsive/visual proof;
- documentation freshness;
- release/production readiness;
- security/reliability/recovery;
- user comprehension and workflow continuity.

## Completion doctrine

Connect before rebuilding.
Consolidate before adding parallel systems.
Measure before optimizing.
Verify before declaring done.
Preserve useful history before removal.
Prefer generated status projections over duplicated manually maintained status prose.

Detailed cross-system convergence belongs in the Integrated Application Program. Exact work belongs in the Task Index. Bounded internals belong in Domain Authorities.
