# Authority and reconciliation

Canonical ownership chain:

`TOKENS -> PRIMITIVES -> COMPOUND COMPONENTS -> WIDGET-SPECIFIC FUNCTIONAL SYSTEM -> WIDGET SHELL -> DASHBOARD GRID -> CERTIFICATION`

The UI Reference Library is a renderer/catalog of production primitives. It is not an independent implementation layer.

## Reconciliation rule

Reconcile older skills, Claude/Codex copies, architecture docs, standalone HTML, CSS, tests, screenshots, branches and current production code.

Classify inherited guidance as:

- KEEP
- UPDATE
- MERGE
- SUPERSEDE
- CONTRADICTION
- OBSOLETE

Current measured/verified code and newer explicit creator decisions outrank stale prose.

## Major reconciled decisions

### Do not force widgets into archetypes

Older documents define KPI/Chart/Form/Generator/etc. archetypes and sometimes require selecting one before designing.

That requirement is superseded.

Archetype labels may be used as historical pattern references, test groupings, or vocabulary, but **a widget must be designed independently around its own creator job and must not be crammed into a predefined visual category**.

### Every widget needs a unique functional identity

Shared primitives do not mean shared internal composition.

Every widget requires a signature component/compound system that:

- is specific to its job;
- is visually recognizable;
- communicates how the tool works;
- assists with its main function.

### Black-stroke legacy guidance

Older widget guidance that requires pure black widget strokes/text/icons conflicts with the newer widget color contract.

Use ViewTube Ink/current widget palette ownership.

Historical screenshots/HTML with black borders may remain as evidence, not current authority.

### Responsive redesign is not mobile-only stacking

Older guidance that solves narrow layouts by stacking everything is incomplete.

Current authority requires bidirectional width × height scaling using:

- canonical primitive sizes;
- density;
- adaptive 24px text where appropriate;
- linked layout equations;
- detail allocation;
- composition reflow only when necessary.

### Title contraction

Titles do not shrink or ellipsize to make room.

They retain canonical title size and may wrap to two lines.

Primary header toggles remain visible in portrait.

## Historical-source rule

Standalone HTML and atlases prove a design idea existed; they do not prove runtime behavior.

Extract useful ideas and rebuild through current:

- tokens;
- primitives;
- data;
- actions;
- accessibility;
- responsive contracts.

## Legacy retirement

Never delete an old skill/reference simply because this skill exists.

Before deletion:

1. compare complete content;
2. migrate every valid unique rule/example;
3. search registries/scripts/agent consumers;
4. update links/routing;
5. verify Claude/Codex paths;
6. run relevant tests/build;
7. record Herald evidence;
8. obtain creator approval for destructive deletion.

Until then, predecessor sources remain superseded/recovery references.
