# Main document authoring

## Product Completion Constitution

Change only when the definition of complete/coherent ViewTube or a global invariant changes. Do not add detailed tasks or transient project status.

## Product Architecture

Change when creator lifecycle, Master Tool composition, durable capability topology, system ownership boundaries or accepted product architecture changes. New UI alone does not necessarily change architecture.

## Capability Registry

Create a CAP record only for a durable ability, not a button/page/API endpoint. One canonical owner. Many tasks/surfaces allowed.

## Integrated Application Program

Change when a cross-system seam, critical dependency, migration/consolidation workstream or application-level completion condition changes. Reference VT/CAP IDs rather than copying detailed task state.

## Domain Authority

Change when bounded intended/current system behavior, owner, contracts, invariants, interfaces or architecture changes. Work logs and conversation history belong elsewhere.

## Specifications

Use for detailed APIs, schemas, design contracts, algorithms, verification profiles or migrations that would overload the Domain Authority.

## Editing checklist

- preserve Production Date;
- update Last Edited;
- audit current main before changing Last Audited Main SHA;
- update registry;
- update supersession/related authorities;
- avoid duplicating status/task lists;
- add decision record when rationale must survive;
- run link/authority verification.
