# Authority and routing

Use docs/registry.json to resolve document role.

## Precedence by concern

1. repository/system instructions and current code/runtime constraints;
2. Documentation Governance for knowledge rules;
3. Product Completion Constitution for global completion doctrine;
4. Product Architecture + capabilities.json for product/capability topology;
5. Integrated Application Program for cross-system convergence;
6. Domain Authority for bounded system truth;
7. Specification for detailed subordinate contracts;
8. Decision for durable choices/rationale;
9. Task Index for work state;
10. receipts/evidence for observed results;
11. plans/audits/reports/references/donors/history for supporting context.

A lower item cannot silently redefine a higher one.

## Naming

Living authorities: brief descriptive names, no dates.
Point-in-time audits/reports/receipts may use dates in metadata and, when useful for immutable snapshots, filenames.
Avoid MASTER, CANONICAL, SOURCE_OF_TRUTH and AUTHORITY in new filenames unless registry governance explicitly requires the term.

## Routing test

Ask: "If this file disappeared, what kind of truth would be lost?"
That answer should match exactly one class/concern.
