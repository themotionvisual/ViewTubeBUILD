# Verification and handoff

## Documentation-only verification

Check:
- document header completeness;
- registry entry;
- class/concern/owner consistency;
- supersession links;
- no competing active authority;
- internal links/paths;
- current-main evidence for implementation claims;
- capability/task/domain links;
- generated-vs-hand-edited boundaries;
- archive/manifests for consolidations.

## Implementation verification

When the mission changes code or UI, follow docs/governance/VERIFICATION.md. Visible changes require screenshot capture plus actual visual analysis. Interact with the feature, verify relevant responsive/device states, fix defects, and repeat until acceptance gates pass or a real blocker remains.

## Handoff receipt

Record:
- mission/task IDs;
- branch/PR/SHA;
- documents changed;
- registry/capabilities changed;
- sources consolidated;
- archive actions;
- tests/validation;
- runtime/screenshot evidence when applicable;
- decisions/conflicts;
- remaining migration;
- one next action.
