# AI Systems Management

Use this reference for cross-system orientation and coordination.

## Start

1. Read `docs/brain/VIEWTUBE_AI_SYSTEMS_MASTER_RESOURCE.md`.
2. Pin current main SHA.
3. Resolve the canonical owner.
4. Read the bounded authority.
5. Check active tasks/plans.
6. Check prior PRs/donors.
7. Classify state as PROVEN / CLAIMED / UNKNOWN.
8. Claim the work if it touches a shared AI architecture seam.

## Never create duplicate owners

Do not create another Brain, analytics store, Channel Profile, Project owner, Asset/Vault owner, Prompt Registry, Outcome Ledger, or repository-agent ledger.

## State language

Use: planned, claimed, in_progress, blocked, partial, implemented_branch, merged_non_main, landed_main_unverified, landed_main_tested, certified, historical, superseded, retired.

A merged PR does not prove current-main integration.

## Completion

Before handoff:
- update bounded authority if behavior/ownership changed;
- update the AI Systems master when cross-system state changed;
- record a completion receipt;
- record tests/evidence;
- state exact main-integration status;
- release or supersede the claim.
